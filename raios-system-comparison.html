raiOS system comparison

Focus: what happens between "code generated" and "allowed to run"?

Most systems handle individual links in this chain very well. raiOS attempts to make the whole chain one coherent, inspectable model. This table deliberately avoids an overall score.

The actual bet

Singularity comes closest to the architectural idea. A Linux stack can assemble nearly every individual part today. raiOS asks whether the complete chain can become a smaller, understandable, non-optional authority model of the OS itself. Partial, in progress, and composable each mean the capability is not a complete built-in one.

All assessments in full
  1. Query live state in a structured form
    • raiOS Partial — Snapshots, devices, and problems
    • Singularity Partial — Strong manifests, limited live view
    • Sculpt Native — Live component graph
    • Fuchsia Native — Topology and Inspect
    • Qubes OS Partial — VM and domain view
    • Linux + Tools Partial — Many separate APIs
  2. Source and confidence of each claim are visible
    • raiOS In progress — Evidence schema exists
    • Singularity Partial — Manifest and digest
    • Sculpt Partial — Report origin is visible
    • Fuchsia Partial — Moniker and diagnostic source
    • Qubes OS Missing — No shared authority hierarchy
    • Linux + Tools Composable — Audit and provenance can be added
  3. Shows the agent what was omitted
    • raiOS Native — Context, sources, and reasons
    • Singularity Missing — No agent-context protocol
    • Sculpt Missing — No agent-context protocol
    • Fuchsia Missing — No agent-context protocol
    • Qubes OS Missing — No agent-context protocol
    • Linux + Tools Composable — Must be built separately
  4. Observation cannot grant authority
    • raiOS Native — Separated in the response type
    • Singularity Partial — Gatekeeper decides separately
    • Sculpt Native — A report is not a capability
    • Fuchsia Native — Inspect does not route capabilities
    • Qubes OS Native — Reading state does not alter policy
    • Linux + Tools Partial — Depends on the API in use
  5. Code remains inert until the gate
    • raiOS In progress — Contract defined; loop not closed
    • Singularity Native — Starts only with a manifest
    • Sculpt Partial — Deployment configuration
    • Fuchsia Partial — Package and manifest
    • Qubes OS Partial — Isolation rather than promotion
    • Linux + Tools Composable — Requires a pipeline
  6. Decision is bound to the exact tested hash
    • raiOS In progress — Reports and hashes exist
    • Singularity Partial — Digest without a test tuple
    • Sculpt Missing — Signature, not test binding
    • Fuchsia Partial — Merkle ID without test binding
    • Qubes OS Missing — Policy applies to the domain
    • Linux + Tools Composable — SLSA and Binary Authorization
  7. Owner approves this exact artifact
    • raiOS In progress — Approval schema exists
    • Singularity Missing — Policy rather than hash approval
    • Sculpt Partial — Owner chooses start or installation
    • Fuchsia Missing — No local promotion gate
    • Qubes OS Partial — Ask per action, not per artifact
    • Linux + Tools Composable — GitOps or admission controls
  8. A missing prerequisite is identified structurally
    • raiOS Partial — Some denials are still generic
    • Singularity Partial — Verifier and gate
    • Sculpt Partial — Reports and logs
    • Fuchsia Partial — Routing diagnostics
    • Qubes OS Partial — Allow, deny, or ask
    • Linux + Tools Composable — Requires a policy engine
  9. Minimal authority per service
    • raiOS Partial — Wasm imports and grants
    • Singularity Native — SIPs and contract channels
    • Sculpt Native — Capability routing
    • Fuchsia Native — Capability routing
    • Qubes OS Partial — At VM and RPC level
    • Linux + Tools Composable — seccomp, SELinux, and VMs
  10. Authority can be revoked precisely
    • raiOS Partial — Limited revoke paths
    • Singularity Partial — Process and gate
    • Sculpt Native — Stop and reroute
    • Fuchsia Partial — Lifecycle and realm
    • Qubes OS Native — RPC, network, and domain
    • Linux + Tools Composable — Policy plus restart
  11. Rollback covers code, authority, and state
    • raiOS In progress — One transaction is the target
    • Singularity Missing — No unified rollback
    • Sculpt Partial — System and configuration
    • Fuchsia Partial — A/B system update
    • Qubes OS Partial — Volume revert; policy separate
    • Linux + Tools Composable — Nix or OSTree; state separate
  12. One protocol spans the entire chain
    • raiOS In progress — Parts already implemented
    • Singularity Partial — Manifest centered
    • Sculpt Missing — Reports, config, and depot are separate
    • Fuchsia Missing — Multiple frameworks
    • Qubes OS Missing — Isolation and policy are the focus
    • Linux + Tools Composable — Composable, not unified
